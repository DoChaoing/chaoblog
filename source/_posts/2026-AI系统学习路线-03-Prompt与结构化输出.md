> **一句话**：Prompt 工程的目标不是写漂亮的话，而是把模型输出变成稳定、可校验、可接入系统的结果。

<!-- more -->

## 1. 好 Prompt 的结构

一个可上线的 Prompt 通常包含：

```text
角色：你是谁
目标：要完成什么
上下文：可用信息是什么
约束：不能做什么
步骤：如何思考或执行
输出格式：必须返回什么结构
失败策略：信息不足时怎么办
```

不要只写：

```text
帮我总结这段内容。
```

更好的写法：

```text
你是企业知识库助手。
请只根据给定资料回答问题。
如果资料不足，请返回“不确定”并列出缺失信息。
输出 JSON：{"answer": "...", "evidence": ["..."], "missing": ["..."]}。
```

## 2. Prompt 的四类任务

| 任务 | 关注点 |
|:--|:--|
| 分类 | 标签边界、冲突处理、置信度 |
| 抽取 | 字段定义、空值、格式校验 |
| 生成 | 风格、长度、受众、禁用内容 |
| 决策 | 规则优先级、理由、审计记录 |

不同任务不要用同一种 Prompt 模板。

## 3. 结构化输出为什么重要

AI 应用不是聊天窗口，后面通常接业务系统。结构化输出能解决：

- 后端可解析；
- 字段可校验；
- 失败可重试；
- 日志可分析；
- 评测可自动化。

常见方案：

| 方案 | 适合场景 |
|:--|:--|
| JSON Prompt | 简单结构 |
| JSON Schema | 字段约束明确 |
| Function Calling | 需要工具调用或参数提取 |
| Pydantic / Zod 校验 | 工程系统接入 |
| Retry + Repair | 模型偶发格式错误 |

## 4. CoT、Few-shot 和模板化

| 技巧 | 使用建议 |
|:--|:--|
| CoT | 适合复杂推理，但不要泄露无意义思维链 |
| Few-shot | 适合分类、抽取、风格对齐 |
| Self-check | 适合检查格式、事实和遗漏 |
| Prompt 模板 | 适合团队复用和版本管理 |

生产里更常用的是“显式步骤 + 结构化理由”，而不是要求模型输出长篇思维链。

## 5. 防 Prompt 注入

Prompt 注入的本质是用户输入试图覆盖系统规则。治理方式：

- 用户输入和系统指令分层；
- 外部文档标记为不可信内容；
- 工具调用前做权限校验；
- 输出前做安全检查；
- 对敏感动作加确认。

面试可以这样说：

> 我不会把检索出来的文档直接当成系统指令，而是放在明确的上下文区域，并要求模型只把它当资料。涉及工具调用时，还会在模型外做参数校验和权限控制。

## 6. 本章产出

你应该沉淀三套模板：

1. 分类 Prompt；
2. 信息抽取 Prompt；
3. RAG 问答 Prompt。

每套模板都要包含：输入、约束、输出 schema、失败策略和示例。
