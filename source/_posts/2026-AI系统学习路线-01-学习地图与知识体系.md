> **一句话**：学习 AI 应用不要从“背模型名”开始，而要先建立一张分层地图：模型基础、Prompt、RAG、Agent、工程化、项目表达。本系列以 `guocong-bincai/ai-interview-guide` 为主要参考源，但会按学习路径重新组织，而不是照搬题库顺序。

<!-- more -->

## 1. 为什么要重新整理

现在资料很多，但容易散成三类：

| 类型 | 优点 | 问题 |
|:--|:--|:--|
| 八股题 | 覆盖面广，适合查漏 | 容易只会背，不知道系统位置 |
| 项目代码 | 接近真实工程 | 新手容易陷入细节，看不出主线 |
| 简历面试 | 能直接用于求职 | 如果底层理解薄，容易讲虚 |

所以学习路线应该从“知识体系”出发，再回到题库和项目。

## 2. AI 应用工程的六层结构

```text
业务问题
  -> Prompt / 结构化输出
  -> RAG / 外部知识
  -> Agent / 工具与规划
  -> 模型服务 / 推理优化
  -> 安全评估 / 可观测 / 部署
```

每一层解决的问题不同：

| 层 | 解决什么 | 典型问题 |
|:--|:--|:--|
| LLM 基础 | 理解模型如何输入输出 | Token、上下文、采样、幻觉 |
| Prompt | 控制模型行为 | 角色、任务、约束、示例、格式 |
| RAG | 给模型可靠知识 | 文档解析、分块、Embedding、检索、重排 |
| Agent | 让模型行动 | 工具调用、记忆、规划、反思、多 Agent |
| 工程化 | 让系统可用 | 延迟、成本、限流、熔断、灰度、监控 |
| 面试表达 | 让经历可信 | STAR、指标、难点、取舍、复盘 |

## 3. 学习顺序

推荐顺序不是“Transformer -> 论文 -> 微调 -> Agent”，而是：

1. 先理解 LLM 的使用边界；
2. 用 Prompt 完成稳定任务；
3. 用 RAG 解决知识和幻觉；
4. 用 Agent 解决多步行动；
5. 用工程化保证线上可用；
6. 用项目表达证明你真的做过。

这样学的好处是每一步都有可见产出。

## 4. 每阶段的验收标准

| 阶段 | 验收标准 |
|:--|:--|
| LLM 基础 | 能解释为什么上下文越长越贵，为什么温度影响稳定性 |
| Prompt | 能写出包含角色、任务、约束、输出格式、失败处理的 Prompt |
| RAG | 能讲清从 PDF 到答案引用的完整链路 |
| Agent | 能实现一次 ReAct 循环，并知道如何防止死循环 |
| 工程化 | 能设计模型路由、限流、重试、日志和评测闭环 |
| 项目表达 | 能把项目讲成“问题、方案、指标、踩坑、复盘” |

## 5. 如何使用原资料库

精炼路线负责“主干”，扩展题库负责“枝叶”。

| 需要 | 去哪里 |
|:--|:--|
| 想快速建立全局框架 | 读本系列 01-07 |
| 某个概念不会 | 查 AI 面试知识库 |
| 需要完整题目和长答案 | 查 AI 面试扩展题库 |
| 要准备项目讲法 | 查项目实战、STAR、简历系列 |

如果你是按 `ai-interview-guide` 原始章节过来的，可以先看 [系统学习总纲](/2026/07/07/2026-AI系统学习路线-00-基于-ai-interview-guide-的系统学习总纲/)，那里把原项目的基础、Prompt、RAG、Agent、模型工程、应用部署、面试技巧全部重排成了学习顺序。

## 6. 常见误区

- 只背名词，不画链路；
- 只会调 API，不知道失败怎么处理；
- 只讲“用了 LangChain”，不讲自己解决的问题；
- 只堆模型名，不讲成本、延迟、指标；
- 只写 Demo，不准备生产级追问。

## 7. 本章总结

AI 应用学习的核心不是“学完所有资料”，而是建立一条能复用的推理路径：

> 业务目标是什么？模型能做什么？缺什么外部知识？是否需要工具行动？如何评估效果？上线后怎么监控？面试时如何证明？
