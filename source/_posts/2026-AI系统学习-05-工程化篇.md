AI 工程化解决的问题是：如何把一个能跑的 Demo，变成可维护、可评估、可上线的应用。

## 评测

AI 应用不能只凭感觉判断效果。至少要有：

- 固定测试集；
- bad case 表；
- Prompt 版本记录；
- 模型版本记录；
- 每次改动后的回归测试。

评测指标不一定复杂，但必须能持续比较。

## 日志

关键日志包括：

| 日志 | 作用 |
|:--|:--|
| 用户输入 | 复现问题 |
| Prompt 版本 | 判断是哪版提示词产生的问题 |
| 检索片段 | 分析 RAG 是否召回正确 |
| 模型输出 | 检查生成质量 |
| 工具 trace | 分析 Agent 执行过程 |
| 耗时和 token | 分析成本和性能 |

日志要注意脱敏，不能把敏感信息随意写入。

## 成本与延迟

优化方向：

- 缓存重复问题；
- 缩短上下文；
- 简单任务用小模型；
- 流式输出改善体验；
- 并行检索和工具调用；
- 限制 Agent 最大轮数。

## 部署与安全

上线前至少考虑：

- 环境变量管理；
- API Key 保护；
- 限流和超时；
- 错误兜底；
- Prompt 注入防护；
- 工具权限边界；
- 回滚方案。

## 本篇练习

给前面的 RAG 或 Agent 项目补齐工程化能力：

1. 增加请求日志；
2. 增加评测集；
3. 记录 token 和耗时；
4. 增加错误处理；
5. 写清楚启动和部署方式；
6. 整理 5 个 bad case。

## 学习目标

工程化篇要解决的问题是：如何让 AI 项目从“能演示”变成“能维护”。

学完后你应该能做到：

- 为 AI 请求设计日志字段；
- 建立最小评测集；
- 估算 token 成本；
- 处理超时、失败和重试；
- 设计基本安全边界；
- 写出部署和回滚方案。

## AI 应用的工程风险

AI 应用和普通后端相比，多了几类不确定性。

| 风险 | 表现 | 工程措施 |
|:--|:--|:--|
| 输出不稳定 | 同一问题多次回答不同 | 固定参数、结构化输出、评测 |
| 幻觉 | 编造事实或引用错误 | RAG、引用来源、拒答 |
| 成本失控 | 上下文过长、Agent 多轮调用 | 限流、缓存、模型路由 |
| 延迟过高 | 检索慢、模型响应慢 | 流式输出、并行、缓存 |
| 安全风险 | Prompt 注入、越权工具调用 | 输入过滤、权限控制、审计 |
| 难以复盘 | 不知道错在哪一步 | 结构化日志和 trace |

## 日志设计

推荐最小日志结构：

```json
{
  "request_id": "req_001",
  "user_id": "u_001",
  "prompt_version": "rag_v3",
  "model": "model_name",
  "input_tokens": 1200,
  "output_tokens": 300,
  "latency_ms": 1800,
  "retrieved_docs": ["doc_1", "doc_2"],
  "tool_calls": [],
  "status": "success",
  "error": null
}
```

不要把敏感信息无脑写进日志。日志要能定位问题，也要保护隐私。

## 评测体系

最小评测体系包括三层：

| 层 | 内容 |
|:--|:--|
| 样例集 | 固定问题、标准答案、期望来源 |
| 自动检查 | 格式、字段、引用、拒答 |
| 人工复核 | 事实正确性、表达质量、业务可接受度 |

不要追求一开始就全自动。很多 AI 应用早期可以“自动指标 + 人工复核”结合。

## 成本控制

成本主要来自：

- 输入 token；
- 输出 token；
- Embedding；
- rerank；
- Agent 多轮调用；
- 工具和外部 API。

优化思路：

| 方法 | 适合场景 |
|:--|:--|
| 缓存 | 高频重复问题 |
| 上下文裁剪 | RAG 检索片段过多 |
| 模型路由 | 简单任务不用大模型 |
| 批处理 | 离线文档处理 |
| 限流 | 防止恶意或异常请求 |

## 安全设计

AI 应用至少考虑：

- Prompt 注入；
- 用户上传恶意文本；
- 工具越权；
- 敏感信息泄露；
- 输出不合规；
- 日志泄露。

简单可行的做法：

1. 对工具做白名单；
2. 危险操作必须人工确认；
3. 不把系统提示词和密钥返回给用户；
4. 对用户输入做长度和类型限制；
5. 对日志做脱敏；
6. 给模型输出加审核或规则过滤。

## 部署清单

上线前检查：

- 是否有 `.env.example`；
- 是否能一键启动；
- 是否有 health check；
- 是否有超时设置；
- 是否有错误兜底；
- 是否有日志；
- 是否有评测集；
- 是否有版本说明；
- 是否有回滚方案。

## 面试表达

> 我会从评测、日志、成本、延迟、安全和部署六个方面考虑 AI 工程化。比如 RAG 项目里，我会记录 prompt 版本、模型、token、检索片段和最终回答，这样当答案错误时能判断是召回问题、生成问题还是资料缺失问题。
