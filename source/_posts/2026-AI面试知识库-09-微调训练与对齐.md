> **TL;DR** — RAG 解决知识来源，微调解决模型行为和任务能力。面试要能讲清全量微调、LoRA、QLoRA、RLHF、DPO，以及如何防灾难性遗忘。

AI 应用工程师不一定亲自训练大模型，但经常要回答“为什么不用微调”“什么时候该微调”。

---

## 1. 微调 vs RAG

| 场景 | 优先方案 |
|:--|:--|
| 私有知识、实时知识 | RAG |
| 输出格式和风格 | 微调 / Prompt |
| 领域任务能力 | 微调 |
| 需要引用来源 | RAG |
| 模型不按流程输出 | Prompt + SFT |

生产里常组合使用：RAG 提供事实，微调改善行为。

---

## 2. LoRA 与 QLoRA

LoRA 冻结原模型，只训练低秩矩阵，降低训练成本。QLoRA 进一步量化基座模型，节省显存。

关键超参：

- rank r：表达能力；
- alpha：缩放；
- dropout：防过拟合；
- target modules：训练哪些层。

---

## 3. RLHF 与 DPO

RLHF 流程复杂：SFT -> 奖励模型 -> PPO。DPO 用偏好数据直接优化，更容易落地。

面试回答：

> RLHF 表达能力强但工程复杂，DPO 更稳定、成本更低。应用团队通常先用 SFT 和 DPO 思路解决偏好对齐。

---

## 4. 灾难性遗忘

微调后模型可能丢失通用能力。缓解：

- 混合通用数据；
- 控制学习率和 epoch；
- PEFT；
- 保留评测集；
- 对比微调前后能力。
