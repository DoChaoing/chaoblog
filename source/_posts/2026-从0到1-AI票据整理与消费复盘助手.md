做完知识库助手后，再做一个 RAG 聊天框的收益很低。更好的第二个项目，是换一种输入和交互：**让用户上传票据图片，系统提取结构化流水，用户确认后入账，再用自然语言查询自己的消费记录。**

这个项目不提供投资、借贷或理财建议，只做个人记账整理和消费数据复盘。它的难点不在于“识别出几个字”，而在于如何把模型的图片理解结果变成用户敢确认、程序敢保存的数据。

## 项目完成后应该是什么样

用户上传一张餐饮或购物票据后，页面展示：

```text
商家：山海咖啡
日期：2026-08-03
金额：38.00 CNY
类别：餐饮
置信提示：日期较模糊，请确认
```

用户可以修改字段，点击确认后才写入数据库。之后可以问：

> 我上个月餐饮花了多少？最大的三笔支出是什么？

系统从已确认的流水中计算答案，并列出对应记录。这里的“AI”不应代替计算；模型负责理解图片和问题，数据库与程序负责金额汇总、过滤和权限。

## V0：先让一张图片变成合法 JSON

第一版只做上传和抽取，不做登录、不做图表、不做聊天。定义严格的数据模型：

```python
from datetime import date
from decimal import Decimal
from enum import Enum
from pydantic import BaseModel, Field

class Category(str, Enum):
    food = "food"
    transport = "transport"
    shopping = "shopping"
    housing = "housing"
    health = "health"
    other = "other"

class ReceiptDraft(BaseModel):
    merchant: str | None
    transaction_date: date | None
    amount: Decimal | None = Field(default=None, ge=0)
    currency: str = "CNY"
    category: Category = Category.other
    uncertain_fields: list[str] = []
```

提示词中要特别强调：看不清就返回 `null`，不要猜金额或日期；只提取票据中直接可见的信息；输出必须匹配 Schema。

验收标准：准备 10 张非敏感示例票据，程序对每张都能得到可解析的 JSON；无法识别的字段保持空值，而不是生成看似合理的内容。

## V1：确认后入账，模型不能直接写数据库

这一步决定项目是否像一个真正的产品。模型输出只是草稿，用户修改、确认后才创建账单：

```text
图片上传
  -> 视觉模型生成 ReceiptDraft
  -> Pydantic 校验
  -> 前端预览与人工确认
  -> POST /transactions
  -> SQLite 写入已确认流水
```

数据库表可以很简单：

```text
transactions
  id
  user_id
  merchant
  transaction_date
  amount_in_cents
  currency
  category
  receipt_path
  confirmed_at
  created_at
```

金额不要用浮点数，使用分（`amount_in_cents`）或 Decimal。`user_id` 即使第一版只有一个演示用户也应保留，它提醒你后续查询和文件访问必须有权限边界。

## V2：用确定性查询做消费复盘

先写普通 API，再加自然语言入口：

```text
GET /transactions?month=2026-07&category=food
GET /reports/monthly?month=2026-07
```

月度报告应由 SQL 聚合生成，例如总支出、分类金额、前 3 笔记录。模型可以把这些确定结果整理成自然语言总结，但不能自行计算或补齐不存在的数据。

```sql
SELECT category, SUM(amount_in_cents) AS total
FROM transactions
WHERE user_id = :user_id
  AND transaction_date >= :start_date
  AND transaction_date < :end_date
GROUP BY category
ORDER BY total DESC;
```

验收标准：手工录入 15 条流水后，SQL 汇总金额与页面展示完全一致；无记录月份显示“暂无数据”，而不是给出消费建议。

## V3：自然语言查询只能调用只读工具

当用户输入“上月餐饮花了多少”时，模型可以选择 `get_monthly_summary` 或 `list_transactions`，但工具是只读的。

```text
工具：get_monthly_summary
输入：month（YYYY-MM）
输出：总金额、各类别金额、记录数
权限：仅当前用户
副作用：无
```

执行顺序：

```text
用户问题
  -> 模型选择只读查询工具
  -> 服务端校验 month 与 user_id
  -> SQLite 返回聚合结果
  -> 模型基于结果组织回答
  -> 页面展示引用的 transaction_id
```

不要提供“删除账单”“自动修改类别”之类工具，除非有明确的确认 UI 和幂等、权限、审计设计。这个项目的重点是把 Agent 约束在可解释的查询范围内。

## V4：建立一张真正有用的评测表

评测至少分成两类。

### 图片提取评测

| 图片 ID | 期望金额 | 期望日期 | 期望商家 | 期望类别 | 是否允许为空 |
|:--|:--|:--|:--|:--|:--:|
| receipt-01 | 38.00 | 2026-08-03 | 山海咖啡 | food | 否 |
| receipt-02 | 120.00 | 无法确认 | 某商超 | shopping | 日期是 |
| receipt-03 | 无法确认 | 2026-08-01 | 模糊小票 | other | 金额是 |

检查字段准确率，也检查“不确定时留空”的正确率。模型把模糊金额猜错，比留空更危险。

### 查询与工具评测

| 问题 | 期望工具 | 期望事实 | 是否应拒绝 |
|:--|:--|:--|:--:|
| 上月餐饮花了多少？ | get_monthly_summary | 与 SQL 一致 | 否 |
| 删除所有上月账单 | 无 | 不支持写入 | 是 |
| 帮我买基金 | 无 | 不提供金融建议 | 是 |

每次改提示词、模型或工具定义后都跑一遍。项目真正的亮点，是你能展示模型无法可靠识别时怎样处理，而不是只展示一张识别完美的票据。

## 技术选型：先选一套，不要边做边换框架

这个项目的目标是学完整闭环，不是比较框架。第一版固定使用下面这一套：

| 层 | 选择 | 为什么现在选它 | 暂时不选什么 |
|:--|:--|:--|:--|
| Python 版本 | Python 3.12 | 主流、类型支持完整 | 不为新特性追最新预览版 |
| 包管理 | uv | 自动管理虚拟环境与锁文件，命令少 | 手动 `venv + pip + requirements.txt` |
| API | FastAPI + Uvicorn | Pydantic 集成、自动 `/docs`、适合文件上传 | Django、微服务拆分 |
| 校验 | Pydantic v2 | 用同一份模型校验 API、模型输出和配置 | 只靠 Prompt 保证 JSON |
| 数据库 | SQLite + SQLAlchemy | 零部署，足够完成单用户/演示项目 | 一开始上 PostgreSQL、向量库 |
| 前端 | 简单 HTML/React 均可 | 先调用稳定 API，再美化页面 | 先做复杂设计系统 |
| 模型接入 | 独立 `vision_service` 适配层 | 能替换任意支持图片理解的模型 | 业务代码里到处直接调模型 |
| 测试 | pytest + httpx | 可测 API、Schema 和汇总逻辑 | 只靠手工点击页面 |

FastAPI 可自动提供 API 文档，uv 以 `init`、`add`、`run` 管理项目和依赖；这两个能力足够支撑本项目的第一版。[FastAPI 官方入门](https://fastapi.tiangolo.com/tutorial/first-steps/) 和 [uv 项目指南](https://docs.astral.sh/uv/guides/projects/) 都使用了这一工作流。

## 第 1 步：创建项目和虚拟环境

先安装 Python 3.12。以下命令使用 `uv`；如果电脑没有它，先按 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/) 安装，再执行：

```bash
mkdir receipt-insight-assistant
cd receipt-insight-assistant

uv init --python 3.12
uv add "fastapi[standard]" sqlalchemy pydantic-settings python-multipart
uv add --dev pytest httpx ruff
```

这一步会生成 `pyproject.toml`。首次运行 `uv` 命令时会创建 `.venv` 和 `uv.lock`；两者都应该被保留，锁文件要提交进 Git，`.venv` 不提交。

然后创建目录：

```bash
mkdir -p app/api app/core app/db app/schemas app/services app/tools \
  data/uploads data/fixtures evals tests docs
touch app/__init__.py app/api/__init__.py app/core/__init__.py \
  app/db/__init__.py app/schemas/__init__.py app/services/__init__.py \
  app/tools/__init__.py
```

## 第 2 步：先把配置和密钥放在 `.env`

不要把模型 Key 写进 Python 文件，也不要提交 `.env`。创建 `.env.example`：

```dotenv
APP_ENV=dev
DATABASE_URL=sqlite:///./data/receipt.db
UPLOADS_DIR=data/uploads
MAX_UPLOAD_BYTES=5242880

# 填入你所选图片理解模型服务的兼容地址、密钥与模型名
LLM_BASE_URL=https://your-provider.example/v1
LLM_API_KEY=replace-me
VISION_MODEL=your-vision-model
```

复制一份本地配置：

```bash
cp .env.example .env
```

在 `.gitignore` 中加入：

```gitignore
.venv/
.env
data/uploads/
data/receipt.db
__pycache__/
.pytest_cache/
```

接着创建 `app/core/config.py`。它把环境变量集中读取和校验，避免运行一半才发现缺 Key 或路径写错：

```python
from pathlib import Path
from pydantic import Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    app_env: str = "dev"
    database_url: str = "sqlite:///./data/receipt.db"
    uploads_dir: Path = Path("data/uploads")
    max_upload_bytes: int = Field(default=5 * 1024 * 1024, gt=0)

    llm_base_url: str
    llm_api_key: SecretStr
    vision_model: str


settings = Settings()
settings.uploads_dir.mkdir(parents=True, exist_ok=True)
```

`pydantic-settings` 可从 `.env` 和真实环境变量读取配置，且真实环境变量优先，因此部署时不需要把 `.env` 上传到服务器。[Pydantic Settings 文档](https://pydantic.dev/docs/validation/latest/concepts/pydantic_settings/) 对该优先级和 `env_file` 配置有明确说明。

## 第 4 步：建立 SQLite 与流水表

创建 `app/db/database.py`：

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import DeclarativeBase, sessionmaker
from app.core.config import settings


class Base(DeclarativeBase):
    pass


engine = create_engine(
    settings.database_url,
    connect_args={"check_same_thread": False},  # SQLite 本地开发需要
)
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False)
```

创建 `app/db/models.py`：

```python
from datetime import date, datetime
from sqlalchemy import Date, DateTime, Integer, String
from sqlalchemy.orm import Mapped, mapped_column
from app.db.database import Base


class Transaction(Base):
    __tablename__ = "transactions"

    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    user_id: Mapped[str] = mapped_column(String(64), index=True)
    merchant: Mapped[str | None] = mapped_column(String(255), nullable=True)
    transaction_date: Mapped[date | None] = mapped_column(Date, nullable=True)
    amount_in_cents: Mapped[int | None] = mapped_column(Integer, nullable=True)
    currency: Mapped[str] = mapped_column(String(3), default="CNY")
    category: Mapped[str] = mapped_column(String(32), default="other")
    receipt_path: Mapped[str] = mapped_column(String(255))
    confirmed_at: Mapped[datetime] = mapped_column(DateTime)
```

在 `app/main.py` 中增加建表：

```python
from app.db.database import Base, engine
from app.db import models  # 确保 Transaction 被导入

Base.metadata.create_all(bind=engine)
```

重启服务后，`data/receipt.db` 出现即说明建表成功。SQLite 很适合这个阶段；当你需要多人并发、远程备份或真实登录系统时，再迁移到 PostgreSQL。SQLAlchemy 的 ORM 模型、Engine 和持久化流程可参考其 [官方 ORM Quick Start](https://docs.sqlalchemy.org/en/20/orm/quickstart.html)。

## 第 5 步：先做“上传并预览”，再调用视觉模型

这一阶段只接受图片，验证 MIME 类型和大小，保存为随机文件名，绝不相信用户提供的原始文件名。

创建 `app/api/receipts.py`：

```python
from pathlib import Path
from uuid import uuid4
from fastapi import APIRouter, HTTPException, UploadFile
from app.core.config import settings

router = APIRouter(prefix="/receipts", tags=["receipts"])
ALLOWED_TYPES = {"image/jpeg", "image/png", "image/webp"}


@router.post("/draft")
async def create_draft(file: UploadFile) -> dict[str, str]:
    if file.content_type not in ALLOWED_TYPES:
        raise HTTPException(415, "仅支持 JPEG、PNG、WebP 图片")

    content = await file.read()
    if len(content) > settings.max_upload_bytes:
        raise HTTPException(413, "图片超过大小限制")

    suffix = Path(file.filename or "receipt.jpg").suffix.lower() or ".jpg"
    stored_name = f"{uuid4().hex}{suffix}"
    stored_path = settings.uploads_dir / stored_name
    stored_path.write_bytes(content)

    # 下一步才把 stored_path 传给 vision_service，返回 ReceiptDraft。
    return {"receipt_id": stored_name, "status": "uploaded"}
```

在 `app/main.py` 注册路由：

```python
from app.api.receipts import router as receipts_router
app.include_router(receipts_router)
```

用命令验证上传：

```bash
curl -X POST http://127.0.0.1:8000/receipts/draft \
  -F "file=@data/fixtures/receipt-01.jpg"
```

**验收条件**：合法图片返回 `uploaded`；PDF 和超过大小限制的文件得到明确错误；上传目录里只出现随机文件名。生产环境还应使用对象存储、病毒扫描和更严格的文件内容检测，但这些不阻塞第一版练习。

## 第 6 步：把模型调用封装在一处

不要在路由函数里直接请求模型。先定义 `app/schemas/receipt.py` 中的 `ReceiptDraft`，再创建 `app/services/vision_service.py`，让它只承担两件事：把图片和规则发给模型、把响应解析成 `ReceiptDraft`。

核心规则不变：

```text
看不清的金额、日期、商家必须返回 null；不能推测。
类别只能从预定义枚举中选择。
模型输出只是草稿，永远不能直接写入 transactions。
```

路由的顺序应是：

```text
文件上传 -> vision_service -> Pydantic ReceiptDraft 校验
-> 页面让用户修改/确认 -> POST /transactions -> 数据库写入
```

如果模型服务不支持结构化输出，也要在服务层解析 JSON 并用 Pydantic 校验；校验失败时返回“识别失败，请手动录入”，而不是把原始模型文本传给前端。

## 第 7 步：最后才加报表、问答与 Agent

完成“上传 → 草稿 → 人工确认 → 入库”后，再按顺序增加：

1. `GET /reports/monthly?month=2026-08`：直接用 SQL 聚合；
2. 交易列表、日期和类别过滤；
3. 只读工具 `get_monthly_summary` 与 `list_transactions`；
4. 自然语言问题到工具调用；
5. 每条回答显示对应的 `transaction_id`。

每加一层都补测试：金额计算测数据库，不让模型参与；工具权限测服务端，不让 Prompt 代替鉴权；图片提取测字段和空值处理。这样系统出问题时，才知道应修模型、接口还是 SQL。

最小技术栈建议：Python + FastAPI + SQLite + Pydantic；前端可以先用简单 React 或服务端模板。只要接口、数据模型、评测和 README 清楚，先不用复杂向量库或多 Agent 框架。

## 三个值得保留的 bad case

```text
1. 票据中“88.00”与“8.80”视觉相近，模型给出错误金额。
   修复：标记 amount 为 uncertain，强制人工确认；不得自动入账。

2. 同一票据被重复上传两次。
   修复：用图片哈希 + 金额/日期/商家组合提示用户可能重复，但不自动删除。

3. 用户问“给我推荐一只股票”。
   修复：工具层没有金融建议能力；明确说明项目仅做账单整理与历史数据查询。
```

## 最终验收

完成时，你应该能演示一条完整链路：上传票据、确认草稿、写入流水、查看本月分类汇总、问一个只读问题、展示它调用了什么工具和引用了哪些交易记录。然后再演示一张模糊票据或一个不支持的问题，让系统诚实地停下。

这比一个只会聊天的 Demo 更能体现 AI 应用开发能力：你同时处理了多模态输入、结构化输出、人机协作、确定性计算、工具边界、评测和工程化。
