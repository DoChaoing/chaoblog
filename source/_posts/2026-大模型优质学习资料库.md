## 如何使用这份清单

先选一条线：

- 想做 AI 应用：从「应用与 Agent」开始，再补「评测与部署」。
- 想理解模型：从「基础与模型原理」依次做项目。
- 想做训练/后训练：完成小 GPT 后再进入「微调与推理能力」。
- 想做本地或线上推理：直接看「推理与部署」，但先准备一个要压测的模型和请求集。

每周最多主学一个项目，其他资料只作为查阅工具。

## 基础与模型原理

| 资料 | 适合谁 | 为什么值得学 | 最小产出 |
|:--|:--|:--|:--|
| [动手学深度学习](https://d2l.ai/) | 深度学习/PyTorch 基础薄弱 | 用可运行代码解释张量、反向传播、注意力等前置知识 | 跑通 attention 示例并解释输入输出 shape |
| [Hugging Face LLM Course](https://huggingface.co/learn) | 已会 Python，想建立 LLM 全景 | 官方持续维护，覆盖 Transformer、数据集与 LLM 生态 | 用 Transformers 完成一个小型文本任务 |
| [minbpe](https://github.com/karpathy/minbpe) | 想真正理解 token | 极小且注释清楚的 BPE 实现，含训练、编码与解码 | 自己训练一个 tokenizer，并比较压缩率 |
| [LLMs-from-scratch](https://github.com/rasbt/LLMs-from-scratch) | 想用 PyTorch 手写 GPT | 从 tokenizer 到预训练、微调的渐进式代码 | 训练小模型并保存配置、曲线、样本 |
| [Stanford CS336](https://cs336.stanford.edu/spring2025/index.html) | 希望理解训练系统 | 将数据、架构、训练、评测放进同一门课 | 做一份小数据训练实验记录 |
| [llm.c](https://github.com/karpathy/llm.c) | 有 CUDA/C 基础 | 直接观察 GPT 训练的底层实现与性能问题 | 成功编译并读懂一次训练日志 |

`llm.c` 是进阶材料，不是入门起点；没有 NVIDIA CUDA 环境时，先完成 Python 路线。

## 微调、后训练与推理能力

| 资料 | 适合谁 | 为什么值得学 | 最小产出 |
|:--|:--|:--|:--|
| [Datawhale Self-LLM](https://github.com/datawhalechina/self-llm) | 希望用中文资料上手开源模型 | 覆盖本地部署、LoRA/全参微调和多模态实践 | 用小数据集完成一次 LoRA，并记录数据格式 |
| [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory) | 已会跑模型，想做规范微调 | 活跃的开源微调平台，包含数据格式、训练与导出配置 | 复现一个 LoRA 配方并对比微调前后样本 |
| [Open-R1](https://github.com/huggingface/open-r1) | 想理解开源 reasoning 训练 | 公开 SFT、GRPO、评测和数据生成的复现实验 | 先读一份 recipe，画出数据与评测流 |
| [Open Instruct](https://github.com/allenai/open-instruct) | 有多卡训练条件/研究兴趣 | AI2 的开放后训练代码，涉及 SFT、偏好优化与可验证奖励 | 复现它的单卡 smoke test，不直接开大训练 |
| [OLMo-core](https://github.com/allenai/OLMo-core) | 对训练基础设施有兴趣 | 公开训练组件、脚本与模型卡，适合读真实训练栈 | 追踪一次官方配置中数据、模型和硬件的关系 |

微调的关键不是把命令跑通。必须留一套固定评测样本，包含成功样例、失败样例和不该回答的样例；否则无法判断模型是否真的变好。

## 应用、RAG 与 Agent

| 资料 | 适合谁 | 为什么值得学 | 最小产出 |
|:--|:--|:--|:--|
| [Full Stack Deep Learning LLM Bootcamp](https://fullstackdeeplearning.com/llm-bootcamp/) | 想做端到端产品 | 将模型、数据、产品和部署放在同一问题中讨论 | 写出一个具体需求的成功与失败定义 |
| [Hugging Face Agents Course](https://huggingface.co/learn/agents-course/unit0/introduction) | 初学 Agent | 从工具、框架到 Agentic RAG 与评测任务都有练习 | 做一个只读、最多两工具的 Agent |
| [smolagents](https://github.com/huggingface/smolagents) | 想看 Agent 循环的最小实现 | 抽象较少，工具、代码 Agent 和 sandbox 边界明确 | 阅读核心循环，并为一个工具加参数校验 |
| [Model Context Protocol](https://modelcontextprotocol.io/specification/2025-06-18/server/index) | 需要接入外部上下文或工具 | 官方规范明确区分 prompts、resources 与 tools | 为一个工具写出权限、输入和副作用说明 |
| [Eugene Yan 的技术文章](https://eugeneyan.com/writing/) | 已有 demo，想了解生产问题 | 长期讨论 RAG、评测、缓存、防御式 UX 与反馈闭环 | 为自己的项目补一份评测表 |
| [Lilian Weng 的技术博客](https://lilianweng.github.io/archives/) | 想系统理解 Agent/评测研究 | 适合在有项目经验后回看机制、任务与评测 | 选一篇文章，写一页问题—方法—局限笔记 |

Agent 的练习顺序应是：先工作流，再只读工具，再带确认的写操作，最后才考虑多 Agent。MCP 是工具接入协议，不会替你解决业务权限和审计。

## 评测与推理部署

| 资料 | 适合谁 | 为什么值得学 | 最小产出 |
|:--|:--|:--|:--|
| [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness) | 需要比较模型或微调效果 | 统一的开源评测框架，支持本地模型、API 与 vLLM | 对一个小模型跑一个固定任务并保存配置与结果 |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) | Mac/CPU 或边缘设备部署 | 覆盖广泛硬件的本地推理项目，适合理解量化与模型文件 | 在本机跑一个量化模型并记录响应速度 |
| [vLLM](https://github.com/vllm-project/vLLM) | 有 NVIDIA GPU，准备服务化 | 聚焦 PagedAttention、continuous batching、prefix caching 和吞吐 | 用自己的请求集做一次并发压测 |
| [vLLM benchmark 文档](https://docs.vllm.ai/en/latest/cli/bench/serve/) | 已能启动 vLLM | 给出在线服务压测工具与指标输出 | 对比不同并发下首 token 延迟与吞吐 |
| [OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/) | 所有准备发布 AI 功能的人 | 提醒 prompt injection、敏感信息泄露等应用风险 | 为项目加入越权与恶意输入测试 |

## 跟踪最新技术的正确方式

以下资料适合“跟踪”，不适合作为第一门课：

- [Hugging Face Learn](https://huggingface.co/learn)：会持续出现新课程，例如 Context 与 Agents。
- [Sebastian Raschka 的博客](https://sebastianraschka.com/blog/)：适合跟进架构、后训练与开源模型的技术解释。
- [vLLM Releases](https://github.com/vllm-project/vllm/releases)：适合观察推理系统的真实演进，如量化、硬件支持、KV cache 与服务架构。
- [awesome-open-source-lms](https://github.com/allenai/awesome-open-source-lms)：用于寻找训练代码、数据和评测也开放的项目，而不只看开放权重。

每遇到一个“新方向”，先回答三个问题：它替换了哪个已有组件？我的项目瓶颈是什么？我用什么指标验证它的收益？答不出来，就先收藏，不开新坑。
