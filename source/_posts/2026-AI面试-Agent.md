Agent 面试不应只回答“模型可以自主调用工具”。更重要的是解释：模型负责做什么决定，程序控制什么边界，执行如何停止和恢复。

## Agent 和普通工作流有什么区别

固定工作流的步骤和分支由程序提前定义，适合规则稳定、风险较高的任务。Agent 让模型根据上下文选择工具或下一步，灵活但更难预测和测试。

如果流程已知，优先使用确定性工作流；只有步骤难以提前枚举时，才让模型参与决策。

## Tool Calling 的执行主体是谁

模型生成工具名和参数，应用程序验证并执行，再把结果返回模型。模型不会因为“调用了工具”就自动获得系统权限。

执行循环包括：模型响应、解析 tool calls、验证工具白名单与参数、授权、执行、记录 tool result、继续生成或结束。

## 如何防止无限循环

设置最大步骤、总超时、token 预算、重复调用检测和工具级超时。工具连续返回相同结果时可以提前终止。达到上限后返回明确状态，而不是默默截断。

## 如何处理状态

区分消息历史、业务状态和执行状态。消息历史用于模型上下文；业务状态存储真实订单或任务；执行状态记录当前节点、重试次数和工具结果。

不要只依赖一段越来越长的聊天记录恢复任务。

## 如何控制权限

工具注册表只是第一层。还需要校验参数、当前用户身份、资源权限和操作风险。写操作可以要求人工确认或使用两阶段执行。

Prompt 中写“不要删除文件”不是权限控制。

## 并行工具调用有什么风险

只读、互不依赖的查询适合并行；存在顺序依赖或写冲突的操作需要串行或事务控制。并行数量还应受限，避免模型一次发起大量昂贵调用。

Ollama 当前官方文档分别展示了单工具、并行工具调用和多轮 Agent loop，这些能力仍需要应用侧执行和管理。

## 如何评测 Agent

不要只评最终答案。记录任务成功率、工具选择正确率、参数正确率、平均步骤、超时率、重复调用率、人工接管率和总成本。

建立包含正常、歧义、权限不足、工具失败和恶意输入的测试集。

## 可观测性需要记录什么

记录模型版本、提示版本、每一步工具、参数摘要、授权结果、耗时、返回摘要、重试和终止原因。敏感数据需要脱敏。

## 一句话总结

Agent 是“模型参与决策的受控执行循环”，不是拥有无限权限的自动化脚本。面试回答应同时覆盖灵活性、状态、安全、终止和评测。
