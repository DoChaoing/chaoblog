AI 面试的核心不是背概念，而是证明你真的理解并做过。最好的证据是项目、评测、日志、bad case 和清晰表达。

## 简历怎么写

不要写：

> 熟悉 RAG、Agent、Prompt 工程。

更好的写法：

> 独立实现企业知识库问答系统，完成文档解析、分块、向量检索、引用来源和评测集建设，覆盖 30+ 条业务问题，并通过 bad case 分析优化检索策略。

简历 bullet 要包含场景、动作、技术点和结果。

## 项目表达

项目讲述可以按这个结构：

1. 背景：为什么做；
2. 目标：解决什么问题；
3. 架构：模块如何拆；
4. 难点：遇到什么问题；
5. 优化：如何定位和解决；
6. 结果：效果和收获。

## 系统设计

常见题目：

- 设计一个企业知识库问答系统；
- 设计一个 AI 客服；
- 设计一个简历筛选助手；
- 设计一个代码审查 Agent；
- 设计一个多工具办公助手。

回答时按这个顺序：

```text
需求目标
  -> 输入输出
  -> 核心链路
  -> 模块拆分
  -> 评测指标
  -> 风险和降级
  -> 成本和部署
```

## 高频问题

| 方向 | 高频问题 |
|:--|:--|
| LLM | Token、上下文、temperature、幻觉 |
| Prompt | 如何稳定输出、如何做结构化、如何做函数调用 |
| RAG | 分块、Embedding、top-k、重排、引用来源 |
| Agent | 工具定义、参数校验、记忆、停止条件、trace |
| 工程化 | 评测、日志、成本、延迟、安全、部署 |

## 面试前检查

准备这些材料：

- 一张项目架构图；
- 一份 README；
- 一组评测问题；
- 五个 bad case；
- 三条简历 bullet；
- 一段 3 分钟项目讲稿；
- 一套系统设计回答模板。

面试官最关心的不是你用过多少框架，而是你能不能把不稳定的模型能力，整理成可使用、可验证、可维护的工程系统。

## 学习目标

面试篇的目标是把前面学到的知识和项目，转换成面试官能判断的证据。

你需要准备：

- 一份简历项目描述；
- 一张项目架构图；
- 一段 3 分钟项目讲稿；
- 一组 RAG / Agent / 工程化追问答案；
- 一份系统设计回答模板；
- 几个真实 bad case。

## 简历项目怎么拆

简历项目建议写成三条 bullet。

模板：

```text
负责/独立实现 {{项目名称}}，面向 {{业务场景}}，完成 {{核心模块}}，解决 {{关键问题}}。
通过 {{技术手段}} 优化 {{指标或体验}}，沉淀 {{评测集/日志/bad case/部署方案}}。
```

示例：

```text
独立实现 AI 知识库助手，支持 Markdown 文档解析、向量检索、引用来源和问答生成，解决内部资料查询效率低的问题。
构建 30+ 条评测问题和 bad case 表，通过调整分块策略和检索 top-k 提升问答命中率，并补充日志记录用于错误复盘。
```

## 3 分钟项目讲稿

讲稿结构：

1. 背景：为什么做这个项目；
2. 目标：要解决什么问题；
3. 架构：模块如何拆；
4. 难点：最难的是哪一块；
5. 优化：你怎么定位并解决；
6. 结果：最后产出了什么；
7. 反思：如果继续做会优化什么。

不要把 3 分钟讲成流水账。重点是“问题、方案、取舍、结果”。

## RAG 高频追问

| 问题 | 回答要点 |
|:--|:--|
| 为什么需要 RAG | 模型不知道私有知识，需要外部资料 |
| 如何分块 | 按标题结构 + 长度限制 + overlap |
| top-k 怎么选 | 结合评测集调整，过小漏召回，过大引入噪声 |
| 如何降低幻觉 | 引用来源、拒答机制、只基于上下文回答 |
| 如何评测 | 标准答案、期望来源、实际来源、错误类型 |
| 答错怎么排查 | 先看召回，再看生成 |

## Agent 高频追问

| 问题 | 回答要点 |
|:--|:--|
| Agent 和工作流区别 | Agent 动态决策，工作流步骤固定 |
| 工具怎么定义 | 名称、描述、参数 Schema、错误返回 |
| 如何避免循环 | 最大轮数、停止条件、任务完成判断 |
| 如何处理工具失败 | 标准错误格式，让模型恢复或退出 |
| 记忆怎么做 | 短期上下文、长期存储、检索召回 |
| trace 有什么用 | 调试、复盘、审计、面试讲解 |

## 工程化高频追问

| 问题 | 回答要点 |
|:--|:--|
| 如何做评测 | 固定样例集 + bad case + 回归测试 |
| 如何控制成本 | 缓存、上下文裁剪、模型路由、限流 |
| 如何降低延迟 | 流式输出、并行检索、减少上下文 |
| 如何做安全 | Prompt 注入防护、工具权限、日志脱敏 |
| 如何排查问题 | request id、prompt 版本、检索片段、模型输出 |

## 系统设计模板

题目：设计一个企业知识库 AI 助手。

可以这样答：

```text
1. 需求：员工查询内部制度、项目文档、技术资料
2. 输入：用户问题、历史对话、权限信息
3. 知识层：文档解析、分块、Embedding、向量库、metadata
4. 检索层：query rewrite、向量检索、关键词检索、rerank
5. 生成层：基于上下文回答，输出引用来源
6. 工程层：日志、评测、缓存、限流、权限、安全
7. 评测：标准问题集、引用准确率、拒答准确率
8. 风险：幻觉、越权、资料过期、成本和延迟
```

## 面试前一天检查

- 简历项目是否能被追问；
- GitHub README 是否完整；
- 架构图是否清楚；
- Demo 是否能打开；
- 评测表是否准备好；
- bad case 是否能讲；
- 项目讲稿是否练过；
- 系统设计模板是否熟悉。

## 最终提醒

如果遇到不会的问题，不要硬编。可以这样回答：

> 这个点我没有在项目里完整实现过，但我会先拆成输入、处理链路、评测指标和风险边界来验证。如果是 RAG 问题，我会先看召回片段；如果是 Agent 问题，我会先看工具调用 trace。

这种回答比假装熟悉更可信。
