> **TL;DR** — RAG 基础不是“把文档向量化”。完整链路包括文档解析、清洗、分块、Embedding、索引、检索、重排、生成、引用和评测。

RAG 是两个项目都重点覆盖的模块。它是 AI 应用落地的主线，也是 Agent 项目的知识底座。

---

## 1. RAG 解决什么

RAG 解决三类问题：

1. 模型不知道私有知识；
2. 模型知识过期；
3. 企业需要答案可追溯。

标准回答：

> RAG 把“找资料”和“生成答案”分开。检索系统负责找可信上下文，大模型负责基于上下文总结和推理。

---

## 2. 完整流程

```text
文档采集 -> 解析清洗 -> 分块 -> Embedding -> 向量索引 -> 检索 -> Rerank -> 生成回答
```

每一步都有面试点：

- PDF/Word/HTML 怎么解析；
- 表格和图片怎么处理；
- chunk size 和 overlap 怎么选；
- embedding 模型怎么选；
- 向量库和普通数据库区别；
- topK 怎么定；
- 生成时如何引用来源。

---

## 3. 分块策略

| 策略 | 适合 |
|:--|:--|
| 固定长度 | baseline |
| 递归字符分割 | 默认推荐 |
| 结构化分块 | Markdown、HTML、文档章节 |
| 语义分块 | 语义边界重要的文档 |
| 父子分块 | 小块召回、大块生成 |

不要背固定 chunk size。要说“用评测集调”，观察 Recall@K、Precision@K、答案准确率、token 成本。

---

## 4. Embedding 和向量库

Embedding 把文本映射成向量。1536 维不是“有 1536 个关键词”，而是模型学习到的语义表示空间。

向量库适合相似度检索，但不负责全部问题。它还需要：

- 元数据过滤；
- 权限控制；
- 索引选择；
- 增量更新；
- 删除和重建；
- 混合检索。

---

## 5. RAG 常见失败

| 失败 | 原因 |
|:--|:--|
| 找不到答案 | 解析、分块、召回失败 |
| 找到但答错 | 上下文噪声、Prompt 弱 |
| 引用不准 | 文档切片和来源映射不清 |
| 成本高 | topK 太大、上下文冗余 |
| 权限泄露 | 检索前后缺少权限过滤 |

面试里要能分层定位，而不是只说“调 Prompt”。
