> **一句话**：面试里最有说服力的不是“我学过”，而是“我解决过什么问题，怎么设计，指标怎么变化，踩过什么坑”。

<!-- more -->

## 1. 推荐做一个主项目

不要做十个零散 Demo。建议围绕一个主项目反复升级：

```text
企业知识库 RAG
  -> 加 Prompt 模板
  -> 加混合检索
  -> 加 Rerank
  -> 加工具调用
  -> 加 Agent
  -> 加记忆
  -> 加评测
  -> 加部署和监控
```

这样每个知识点都能落在同一个项目里。

## 2. 项目结构

一个可讲的 AI 项目至少包含：

| 模块 | 面试价值 |
|:--|:--|
| 文档 ETL | 体现数据处理能力 |
| RAG 检索 | 体现核心 AI 应用能力 |
| Prompt 模板 | 体现输出控制能力 |
| 工具调用 | 体现 Agent 能力 |
| 评测集 | 体现工程严谨性 |
| 可观测性 | 体现生产经验 |
| 部署 | 体现完整交付能力 |

## 3. 简历写法

不要写：

```text
熟悉 LangChain、Milvus、FastAPI。
```

改成：

```text
设计并实现企业知识库 RAG 问答服务，负责文档解析、语义分块、混合检索和流式问答；
通过 BM25 + 向量召回 + reranker 优化，将自建评测集 Recall@5 从 X 提升到 Y；
接入 trace 和 token 成本统计，支持线上 bad case 回归。
```

重点是动作、方法和结果。

## 4. STAR 面试表达

| 部分 | 应该讲什么 |
|:--|:--|
| Situation | 项目背景和业务问题 |
| Task | 你负责哪部分 |
| Action | 你怎么设计和优化 |
| Result | 指标、效果、复盘 |

示例：

> 当时业务客服需要快速查询内部制度，但原系统只能关键词搜索，命中率低。我负责搭建 RAG 问答链路。先做文档解析和 baseline 向量检索，后来发现精确术语召回差，于是加入 BM25 混合检索、RRF 融合和 reranker，并建立 100 条评测集做回归。最终 Recall@5 提升到 X，回答可引用来源，线上问题也能通过 trace 排查。

## 5. 面试高频追问

| 追问 | 回答方向 |
|:--|:--|
| 为什么不用微调？ | 私有知识变化快，需要引用来源，所以先用 RAG |
| 分块怎么做？ | 按标题、段落、语义边界，保留元数据 |
| 效果怎么评估？ | Recall@K、faithfulness、bad case |
| Agent 怎么防死循环？ | 最大轮数、状态机、工具白名单、失败计数 |
| 成本怎么控制？ | 模型路由、缓存、限流、上下文压缩 |
| 安全怎么做？ | 权限过滤、Prompt 注入防护、PII 脱敏 |

## 6. 项目答辩结构

讲项目时按这个顺序：

1. 业务问题；
2. 系统架构；
3. 核心链路；
4. 关键难点；
5. 优化过程；
6. 指标结果；
7. 踩坑复盘；
8. 如果重做会怎么改。

## 7. 本章产出

最终你应该准备三份材料：

- 一页项目架构图；
- 一份简历项目 bullet；
- 一份 3 分钟项目口述稿。

这三份材料比背 100 道题更能证明能力。
