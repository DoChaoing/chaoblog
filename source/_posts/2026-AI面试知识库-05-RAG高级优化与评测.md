> **TL;DR** — 高级 RAG 面试重点是召回、排序、压缩和评测：Query 改写、HyDE、混合检索、RRF、Rerank、GraphRAG、RAGAS、bad case 闭环。

RAG 能跑通不难，难的是做准、做快、做便宜、做可解释。

---

## 1. Query 改写与 HyDE

用户问题常常不适合直接检索。

- Query Rewrite：补全上下文；
- Query Expansion：扩展多个问法；
- Multi-Query：多视角检索；
- HyDE：生成假设答案，再用假设答案检索。

风险是 query 漂移，所以必须配合评测。

---

## 2. 混合检索与 RRF

向量检索擅长语义，BM25 擅长关键词和编号。生产系统常用：

```text
Vector topK + BM25 topK -> RRF 融合 -> Rerank -> TopN 上下文
```

RRF 的优势是不用强行比较不同检索器的原始分数，而是融合排名。

---

## 3. 向量索引选型

| 索引 | 特点 |
|:--|:--|
| Flat | 精确但慢，适合小规模和评测 |
| HNSW | 召回高、速度快，内存较高 |
| IVF | 聚类倒排，适合大规模 |
| IVF-PQ | 压缩省内存，有精度损失 |
| LSH | 哈希近似，适合特定场景 |

回答时要讲 trade-off：速度、召回、内存、构建成本、更新频率。

---

## 4. Rerank 和上下文压缩

向量相似不等于答案相关。Rerank 用更强模型对候选文档重新排序。

上下文压缩用于减少无效 token：

- LLM 提取；
- embedding 过滤；
- 规则裁剪；
- 保留引用和关键句。

注意：压缩不能压掉证据。

---

## 5. GraphRAG

GraphRAG 适合多跳关系问题。它不是只返回文档片段，而是结合实体、关系和子图。

适合：

- 企业组织关系；
- 项目负责人查询；
- 金融、医疗、法律知识网络；
- 多跳推理。

---

## 6. RAG 评测

常见指标：

- Recall@K；
- Precision@K；
- MRR / nDCG；
- Faithfulness；
- Answer Relevance；
- Context Precision；
- Context Recall；
- 延迟和成本。

评测闭环：

```text
收集 bad case -> 标注失败原因 -> 调整分块/检索/Prompt -> 回归评测 -> 灰度上线
```
