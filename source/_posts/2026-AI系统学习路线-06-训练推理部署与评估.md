> **一句话**：AI 工程化的核心是让效果、成本、延迟和风险都可控。

<!-- more -->

## 1. 什么时候微调，什么时候 RAG

| 需求 | 更适合 |
|:--|:--|
| 私有知识、实时知识 | RAG |
| 固定输出风格 | 微调 |
| 特定任务能力 | 微调 |
| 要求引用来源 | RAG |
| 行业术语理解 | RAG + 少量微调 |
| 降低 Prompt 长度 | 微调 |

一句话：

> RAG 解决知识来源，微调解决行为模式。生产里常常组合使用。

## 2. 微调基本概念

| 概念 | 说明 |
|:--|:--|
| SFT | 用高质量指令数据做监督微调 |
| LoRA | 低秩适配，只训练少量参数 |
| QLoRA | 量化后做 LoRA，省显存 |
| RLHF | 用人类反馈做强化学习 |
| DPO | 直接用偏好对优化 |

面试不一定要求训练大模型，但要能讲清为什么、用什么数据、怎么评估。

## 3. 推理优化

推理分两段：

```text
Prefill：处理输入上下文
Decode：逐 token 生成输出
```

优化方向：

| 问题 | 优化 |
|:--|:--|
| 首 token 慢 | 缩短输入、缓存、模型路由 |
| 生成慢 | KV Cache、批处理、投机解码 |
| 显存不够 | 量化、PagedAttention |
| 成本高 | 小模型路由、缓存、限流 |
| 并发低 | vLLM/SGLang、动态 batching |

## 4. 部署架构

AI 应用不要让业务服务直接散落调用模型。更好的结构：

```text
业务服务
  -> LLM Gateway
  -> Model Router
  -> Provider / Self-hosted Model
  -> Trace / Metrics / Billing
```

LLM Gateway 负责：

- API key 管理；
- 模型路由；
- 限流；
- 重试和熔断；
- 成本统计；
- 日志脱敏；
- 统一 trace。

## 5. 评估体系

AI 应用评估要分层：

| 层 | 看什么 |
|:--|:--|
| 单轮答案 | 准确性、相关性、格式 |
| RAG | 召回、忠实度、引用 |
| Agent | 成功率、工具错误、循环次数 |
| 安全 | PII、越权、注入、违规内容 |
| 线上 | 延迟、成本、满意度、失败率 |

评估不是上线前跑一次，而是每次改 Prompt、模型、分块、工具都要回归。

## 6. 可观测性

必须记录：

- request id；
- prompt 版本；
- 模型名；
- token 用量；
- 检索片段；
- 工具调用；
- 错误栈；
- 最终答案；
- 用户反馈。

没有 trace 的 Agent，线上问题几乎无法排查。

## 7. 本章产出

给你的 RAG/Agent Demo 加上：

- LLM Gateway 封装；
- 模型路由；
- 请求日志；
- token 成本统计；
- bad case 回归脚本；
- 简单 dashboard 或日志查询。
